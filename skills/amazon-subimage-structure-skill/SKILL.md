# Amazonサブ画像6枚 構成案・ワイヤーフレーム制作

## 目的

Amazon商品ページに掲載するサブ画像6枚について、購入判断に必要な訴求を整理し、各画像の役割・コピー・差し込み素材・レイアウト指示・ワイヤーフレームを作成する。

このスキルは、レビュー分析や商品調査そのものではなく、分析済みの訴求情報をもとに「6枚の画像構成へ落とし込む」ために使う。

## Figmaテンプレートへの一括出力

商品情報・レビュー分析・市場調査とFigmaテンプレートが揃う場合は、初回の出力で次を完了する。

- `素材`、`トンマナ`、`ムードボード`、1〜6枚目の`内容`と`使用画像`を埋める。
- 各枚の必要素材を、背景、商品画像、イラスト／アイコンに分けて個別ファイルとして生成する。素材シートだけで代用しない。
- `使用画像`には個別画像名を記載し、汎用モックの差し替えや仕様未確定の注釈だけを追加する。注釈は「〜は公式商品写真へ差し替える必要があります。」「〜は仕様の確認が必要です。」で統一する。
- 生成素材は実行環境からDownloadsを動的に解決し、`<Figmaファイル名>_画像`フォルダに格納する。

## 入力として受け取る情報

必須:

- 商品名
- 商品カテゴリ
- 商品概要
- ターゲット
- 制作目的
- 商品の主な特徴
- 強く訴求すべき点
- 最低限伝えるべき点
- あえて訴求しない点、または弱い点
- NG表現、注意表現

あると望ましい:

- ASIN
- Amazon商品URL
- 既存の商品ページ情報
- 競合商品URL
- 競合サブ画像
- レビュー分析結果
- 市場調査結果
- ブランド情報
- 使用できる素材
- 使用できない素材
- 希望デザイン
- 薬機法、景表法、Amazon規約上の注意点

## 基本方針

- 6枚全体で自然な購買導線を作る。
- 1枚ごとの役割を重複させない。
- 1枚目には最も強い差別化訴求を置く。
- 最低限伝えるべき仕様・内容量・使い方・素材などは、購入判断に必要な範囲で補足する。
- 訴求不要な内容、弱み、根拠のない強みはメイン訴求にしない。
- 断定表現、効果効能表現、誇大表現、No.1表現、最高級表現は根拠がある場合のみ慎重に使う。
- Amazon上で視認性が高く、スマホでも読める構成にする。
- デザイン指示は制作担当者がそのまま画像化しやすい粒度にする。

## 構成確認からFigma化までの制作フロー

作業中の確認は必ず次の順で行う。

### Step 1. テキストにて構成内容を確認

まず画像は生成せず、テキストで6枚の構成案を提示する。

提示内容:

- 各画像の役割
- メインコピー
- サブコピー
- 入れる情報
- 差し込み素材
- 生成可能な画像素材
- 実物写真を使うべき画像素材
- レイアウト方針
- デザイン指示
- 避ける表現

ユーザーが修正点を出した場合は、この段階で訴求順・コピー・情報量・素材指定を調整する。

### Step 2. 必要画像素材を生成・整理

テキスト構成が固まったら、各画像で必要になる素材を整理し、生成できるものは必要に応じて生成する。

素材整理の目的:

- 既存写真が必要な素材と、AI生成で用意できる素材を分ける
- 画像ワイヤーフレームやFigma化で使う写真枠の内容を具体化する
- 完成デザイン時に素材不足で止まらないようにする

生成してよい素材:

- 背景素材
- 商品カテゴリに合う使用シーン
- 机、棚、屋内外、ギフト、手元、生活空間などの雰囲気写真
- 商品カテゴリに関連する一般的な小物、道具、素材、質感
- 自然、街、室内、抽象背景など、商品固有性が低いイメージ
- テクスチャ、パターン、装飾用素材

既存写真・提供素材を優先すべき素材:

- 実際の商品パッケージ
- 商品ラベル、ロゴ、ブランド表記
- 正確な形状・容量・色・印字が必要な商品本体
- 実在する人物、店舗、工場、農園、認証マーク
- 根拠や権利確認が必要な公式素材

素材生成時のルール:

- 生成素材には、実物と誤認させる断定的な表現を付けない。
- 商品写真が必要な枠は、原則として実物写真を使う前提にする。
- AI生成した商品パッケージを、実在商品の正確な商品写真として使わない。
- 生成素材には文字やロゴを入れない。文字はFigmaまたは最終デザイン側で編集可能に置く。
- Amazon審査上リスクがある効能表現、No.1表現、認証風マークを生成素材に含めない。
- 素材生成後、使う素材・使わない素材を整理してから画像ワイヤーフレーム確認へ進む。

### Step 3. 画像にて確認

テキスト構成と必要素材の方向性が固まったら、簡易ワイヤーフレーム画像を生成して確認する。

画像確認の目的:

- テキストの配置感を確認する
- 写真や素材の差し込み位置を確認する
- テキスト枠、見出し枠、アイコン枠、写真枠のバランスを確認する
- 6枚全体の流れを俯瞰する

画像生成時のルール:

- まずは完成デザインではなく、簡易ワイヤーフレームとして生成する。
- 6枚を一覧で見たい場合は、3列 x 2行のコンタクトシートにする。
- 各画像を個別に詰めたい場合は、1枚ずつ正方形で生成する。
- 写真として差し込む素材は、必ず `商品写真（写真）`、`ドリッパー（写真）`、`使用シーン（写真）` のように `（写真）` を付ける。
- イラスト、アイコン、装飾、テキスト枠は `（写真）` を付けない。
- 写真枠、テキスト枠、補足情報枠、見出し枠が分かるようにする。
- ワイヤーフレーム上の文字は最終確定コピーと完全一致しなくてもよいが、意図が分かる短い文言にする。
- 画像生成後、必要に応じてテキスト構成へ戻って修正してから再生成する。

### Step 4. Figma/SVG編集可能要素として再構築

画像ワイヤーフレームの方向性が固まったら、確定したテキスト構成をもとにFigmaへ編集可能な要素として再構築する。

重要:

- 生成済みPNG/JPG画像を自動分解して編集可能化しようとしない。
- 画像生成物は見た目確認用の参照として扱う。
- Figma化では、確定済みの構成案をもとにテキスト、写真枠、図形、線、バッジ、背景を再作成する。
- 生成済み画像素材を使う場合は、写真枠や背景枠へ差し込む。コピーやラベルは画像内に焼き込まず、Figmaテキストで置く。
- 必要に応じてSVGを使ってよいが、基本はFigma上で操作できるテキストノード・長方形・線・グループとして作る。
- 各サブ画像は正方形フレームとして作成する。
- 推奨サイズは `1600 x 1600px` または `2000 x 2000px`。テストや軽量確認では小さめでもよい。
- 6枚を一覧確認したい場合は3列 x 2行で配置する。
- 各フレーム名は `1枚目 / 第一訴求` のように、枚数と役割が分かる名前にする。
- 写真差し込み枠は長方形または図形で作り、枠内テキストに必ず `（写真）` を付ける。
- メインコピー、サブコピー、仕様文言は編集可能なFigmaテキストとして置く。
- 写真枠は後からデザイナーが差し替えやすいよう、塗り・枠線・ラベルを持つ独立要素にする。
- 画像確認の見た目を完全再現するより、後から操作・修正しやすい構造を優先する。

## 写真差し込み表記ルール

写真として用意・撮影・生成・購入素材で差し込む想定のものには、必ず名称の後ろに `（写真）` を付ける。

例:

- `商品写真（写真）`
- `使用シーン（写真）`
- `ドリッパー（写真）`
- `コーヒー豆（写真）`
- `ギフトシーン（写真）`
- `農園風景（写真）`
- `人物の手元（写真）`

`（写真）` を付けないもの:

- メインコピー
- サブコピー
- アイコン
- 矢印
- 線
- ラベル
- バッジ
- テキスト枠
- 背景色
- 装飾パターン

## 推奨する6枚構成

商品カテゴリや訴求に応じて調整してよいが、基本は次の流れにする。

### 1枚目: 第一訴求・差別化

- 役割: 最も強い魅力を一目で伝える。
- 置く内容: 商品の強み、ターゲットに刺さるベネフィット、競合との差。
- 見せ方: 商品写真を大きく置き、メインコピーを短く強く見せる。
- 注意: 根拠のないNo.1、最高級、絶対表現は避ける。

### 2枚目: 主要特徴・品質

- 役割: なぜ良い商品なのかを説明する。
- 置く内容: 素材、産地、製法、機能、品質、こだわり。
- 見せ方: 写真・アイコン・短い説明で理解させる。
- 注意: 情報を詰め込みすぎない。

### 3枚目: 使用シーン・自分ごと化

- 役割: 購入後の使い方や生活内のイメージを見せる。
- 置く内容: 使用シーン、利用タイミング、誰に合うか。
- 見せ方: ライフスタイル写真や具体的な場面で伝える。
- 注意: ターゲットから外れた人物像や過度な演出にしない。

### 4枚目: 悩み解決・不安解消・比較

- 役割: 購入前の迷いを解消する。
- 置く内容: 悩み、競合比較、選ばれる理由、よくある不安への回答。
- 見せ方: 比較表、チェックリスト、Before/After風の整理。
- 注意: 他社を不当に下げる表現は避ける。

### 5枚目: 仕様・信頼性・最低限情報

- 役割: 購入判断に必要な情報を補足する。
- 置く内容: サイズ、容量、セット内容、使い方、原材料、対応条件、注意点。
- 見せ方: アイコン、スペックカード、図解で整理する。
- 注意: メイン訴求よりも補足情報として扱う。

### 6枚目: まとめ・購入後イメージ

- 役割: 6枚全体の訴求をまとめ、購入後の満足を想像させる。
- 置く内容: 主要ベネフィットの再提示、自宅用・ギフト用などの締め。
- 見せ方: 商品写真、使用シーン、短い箇条書きで安心感を作る。
- 注意: 1枚目と同じ内容の繰り返しにしない。

## 画像生成プロンプト方針

素材生成や画像確認に進む場合は、以下を守る。

### 素材生成プロンプト

- 商品固有の正確なパッケージ、ロゴ、ラベル、認証マークは生成しない。
- 生成素材には文字を入れない。
- 使用シーン、背景、質感、小物は、商品カテゴリとデザイントーンに合わせる。
- 素材単体で使いやすいよう、余白と明確な被写体を確保する。
- Amazon審査上リスクのある効能・No.1・保証表現を連想させる素材にしない。
- 必要に応じて、背景なし風、俯瞰、横長、正方形、寄りなど、使う枠に合わせた構図を指定する。

### ワイヤーフレーム確認プロンプト

画像確認に進む場合は、以下をプロンプトに含める。

- Amazonサブ画像6枚の簡易ワイヤーフレームであること
- 完成デザインではなく確認用であること
- 6枚一覧の場合は3列 x 2行であること
- 各パネルに `1枚目` から `6枚目` のラベルを入れること
- 写真差し込み枠には必ず `（写真）` を付けること
- テキスト枠、写真枠、ラベル、アイコン枠が分かること
- 商品カテゴリに合う色・トーンを反映すること
- 過度な完成度よりも、構造の分かりやすさを優先すること

## Figma/SVG化方針

Figma化を行う場合は、以下を守る。

- Figma新規ファイルが必要な場合は、Figmaの `create_new_file` 手順に従って作成する。
- Figmaへ書き込む場合は、Figmaの `use_figma` 手順に従う。
- 画像生成したワイヤーフレームはラスター参照として扱い、編集可能要素へは確定構成から再構築する。
- 各画像は個別の正方形フレームにする。
- フレーム内要素は、可能な限り以下の単位に分ける。
  - 背景
  - 内側の枠線
  - 見出しテキスト
  - サブコピー
  - 写真差し込み枠
  - 写真差し込み枠ラベル
  - 仕様カード
  - バッジ
  - 区切り線
  - 装飾
- Figma上で後からコピー修正、素材差し替え、位置調整ができる状態を優先する。
- 写真枠は `商品写真（写真）`、`ドリッパー（写真）` のようなラベル付きプレースホルダーにする。
- テキストはアウトライン化しない。
- 編集可能性を失うため、全体を1枚のSVGまたはPNGとして貼るだけで完了しない。
- 完成デザインではなくワイヤーフレーム段階では、色数・装飾・写真表現を控えめにする。

## 禁止事項

- 入力されていない効果効能を追加しない。
- 商品の弱みを根拠なく強みに変換しない。
- 競合より明確に優れている根拠がない内容を第一訴求にしない。
- 6枚すべてで同じ訴求を繰り返さない。
- 薬機法、景表法、Amazon規約上リスクのある断定表現を使わない。
- 写真差し込み枠であるにもかかわらず `（写真）` を省略しない。
- ユーザー確認前に最終デザイン風の画像生成へ進まない。
- Figma化で生成画像を1枚貼り付けただけの編集不能な状態にしない。
- テキストをアウトライン化して編集不能にしない。
- AI生成した商品パッケージを実物の商品写真として扱わない。
- 生成素材にロゴ、ブランド名、ラベル文字、認証マークを勝手に入れない。

## 最終品質基準

- 6枚それぞれの役割が明確である。
- 強く訴求すべき点が目立つ位置に反映されている。
- 最低限伝えるべき点が不足していない。
- 訴求不要な内容がメイン化されていない。
- 写真差し込み素材とテキスト要素の区別が明確である。
- 生成してよい素材と、実物写真・提供素材を優先すべき素材が分かれている。
